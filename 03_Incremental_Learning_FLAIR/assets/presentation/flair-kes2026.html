Incremental learning's trap

The same weights that learned person 1 are now learning person 2. Incremental learning forces the network to reuse the old parameters; it can't add new ones.

How incremental learning erases

As gradients flow backwards from person 2's errors, they push the shared weights in new directions. Incremental learning overwrites person 1's fingerprint in real time.

After learning ten people sequentially, accuracy on person 1 drops from 90% to 46%. This sharp loss of prior knowledge, this is called catastrophic forgetting. It's not a gradual fade; it's a collapse.

Contribution · the proposal

FLAIR: FiLM-based Learning with Adaptive Importance and Replay

Combines all three families in a single objective

Rather than pick a side of the stability–plasticity trade-off, condition the network per user, replay past users through their own conditioning, and protect the shared backbone more as it becomes more valuable.

Per-task FiLM conditioning
Affine modulation γt·h + βt on a shared backbone. Specialisation without parameter growth.
Multi-head blending conditioning
Shared head and task head mixed at a fixed ratio, inside the same objective.
FiLM warm-start conditioning
A new user starts from the most statistically similar previous user, not from identity.
Task-aware replay replay
Buffer stores task identity, so each replayed sample is routed through its own FiLM branch.
Adaptive replay weight replay
Users that are actually being forgotten get proportionally more replay emphasis.
Fisher + RetroBoost regularization
Online importance, scaled up as the number of completed users grows.

All six train under one loss, none is a post-hoc correction stage.

The design principle: reserve the shared backbone for common structure, and use lightweight task-specific components for differences between operators.

Method · architecture

A shared backbone, modulated per user

The forward path is shared, but the task identity changes how features are interpreted. Past samples are therefore replayed through their original task branch, while completed task-specific parameters are frozen.

Method · training objective

Four terms, one backward pass

ℒ  =  ℒtask  +  α ℒlogit  +  β ℒreplay  +  λ/2 · ℒreg

One update sees the present and the past at the same time: it learns the current operator, rehearses earlier operators, and limits changes to shared parameters that carry important prior knowledge.

ℒtask
Fit the operator in front of you. Plain MSE between predicted and recorded joint velocities on the current batch.
α ℒlogit
Keep your old opinions. Dark-knowledge distillation, replayed samples must still produce the logits the model produced back when it owned that task.
β ℒreplay
Keep the old ground truth too. Direct MSE on buffered actions, weighted by wr, higher for users currently being forgotten.
λ/2 · ℒreg
Do not move what matters. Fisher-weighted penalty Σ Ωi(θi − θ*i)² anchoring shared parameters to their post-previous-task values.

α = β = 0.5 · λ = 5000 · buffer = 10 000 · Fisher samples = 2000

Method · mechanisms in detail

What each mechanism actually does

Task-aware replay routing
The buffer stores (o, a, â, t), identity included. Each replayed sample passes through its own FiLM branch. Replaying through the wrong branch would apply the wrong modulation and produce misleading gradients.
Adaptive replay weighting
Track each task's peak and current R². Weight replayed samples by the gap:
wr = 1 + 5·max(0, R²peak − R²current)
RetroBoost
Online EWC accumulates Ω ← γΩ + F. FLAIR then scales it by how much has been learned so far, the shared backbone gets more valuable, so protect it harder:
Ω ← (1 + 0.1·|completed|) · Ω
FiLM warm-start
Match the new user's input statistics against every previous user by cosine similarity, then clone that user's FiLM parameters as the starting point:
t* = arg max cos([μt; σt], [μt′; σt′])

Multi-head blending

â = (1−αh)·fshared(h(L)) + αh·ft(h(L))

αh = 0.3, the shared head carries most of the prediction; the per-user head supplies the remainder. After task t finishes, its FiLM parameters and its head are frozen, so nothing retroactively rewrites them.

Joint Training is only an upper bound when one shared representation can serve every user. Here it cannot.

Specialisation

FiLM gives each operator their own feature modulation. A single set of weights fitted to all ten averages them into a compromise nobody is best served by.

Regularisation effect

Replay plus Fisher penalty act as a brake on overfitting to whoever arrived most recently, Joint Training has no such brake.

Transfer

Warm-start hands each new user a starting point borrowed from the most similar previous user, so adaptation begins from structure rather than identity.

Joint Training still shows the best backward transfer (−0.004), unsurprising, since it never stops seeing old data. Its weakness is final per-user fit, not retention.

Conclusion · what to take away

Three things worth keeping

01

Hybrid beats single-family. Combining conditioning, replay and regularisation under one objective gave ACC 0.690 with forgetting 0.017, better on both axes than any component family alone.

02

"Upper bound" is conditional. When users genuinely differ, joint retraining is not a ceiling, per-user conditioning cleared it by 0.046 while using 1280× less memory.

03

Deployable, not just accurate. 1.3 MB of overhead and no stored history, the profile an assistive robot living with a growing user population actually needs.

Where it is limited

One benchmark so far · task identity required at train and test time · 3.6× slower than DER++, though still 13.8× faster than joint retraining.

Where it goes next

Standard CL benchmarks for generalisability · task-agnostic operation via inferred identity · more operators, and longer sequences per operator.
